# Tread — Program Engine Spec

Build the complete training program: data, scheduling, progression, adaptation,
retests, and the maintenance phase.

**Do not change the UI.** Every screen, card, style, and layout stays exactly as
it is. You are filling existing components with real data and real logic.

---

## HARD CONSTRAINT

Forbidden:
- Any style, colour, spacing, size, font, radius, shadow, or layout change
- Adding, removing, moving, or reordering any visual component
- New screens, sheets, or modals

Allowed:
- Data files, models, engines, storage, handlers, conditionals
- Replacing hardcoded literals with computed values
- Wiring existing components to routes
- Adding string literals into slots that already render

If a task needs a visual change, stop and list it under
`NEEDS_DESIGN_DECISION`. Do not implement it.

---

## What exists today

- `program.ts` has a small hardcoded day list. Days 15–28 only.
- `program-page.tsx:144` prints `Block 2 of 4 · 14 days` — the `4` is a literal.
- `day-page.tsx` has four branches but no route pushes it.
- Retest data exists for day 14 only.
- No progression, no adaptation, no maintenance.
- Home brief has 1 of 11 states.

## What you are building

A deterministic engine that, given the user's profile and their logged history,
returns exactly what to show for any day.

## 1.1 Exercise catalogue

Create `src/entities/program/model/exercises.ts`.

```ts
type Exercise = {
  id: string
  title: string            // shown in UI
  category: 'Fitness' | 'Mobility' | 'Habit' | 'Recovery'

  position: 'standing' | 'seated' | 'wall'
```

# PART 2 — PROGRESSION

## 2.1 Heel raises (the pain engine)

Prescription changes by block. This is the mechanism that produces the effect;
without it the exercise is just calf work.

| Block | Sets × reps | Load | Tempo |
|---|---|---|---|
| 1 | — | — | not in program |
| 2 | 3 × 12 | bodyweight | 3-2-3 |
| 3 | 4 × 10 | backpack | 3-2-3 |
| 4 | 5 × 8 | backpack, heavier | 3-2-3 |
| 5 | 5 × 8 | backpack, heavier | 3-2-3 |
| 6 | 3 × 15 | bodyweight, no towel | 3-2-3 |

**Must be visible in the UI.** Today's Tasks currently shows
`Heel raises · Fitness · 7 min`. It must show the prescription — use the
existing subtitle slot, no new element:

```
Heel raises        3 × 12       7 min
```

On the first Strength day of a block where load changes, the session player
shows the block's load note in the existing rationale slot:

```
Block 3:  "Add a backpack. Heavy enough that the last rep is the last rep."
Block 4:  "Add more. Eight reps should be all you have."
Block 6:  "Towel off. Bodyweight. This is the version you keep doing."
```

# PART 3 — ADAPTATION ENGINE

Create `src/entities/program/model/adapt.ts`.

```ts
function resolveDay(input: {
  dayNumber: number
  block: Block
  kind: DayKind
  painToday: number | null
  pain7dAvg: number | null
  hoursOnFeetYesterday: number | null
  hoursBaseline: number | null
  daysSinceLastSession: number
  progressionOffset: number      // 0 = on plan, -1 = one step back
}): ResolvedDay
```

Pure function. Same input, same output. No randomness, no LLM.

## 3.1 Rules, first match wins

| # | Condition | Result |
|---|---|---|
| 1 | `painToday >= 7` | **Offload.** Drop every `loadsFascia` exercise. Keep track-B only. Cap at 3 min. |
| 2 | `painToday - pain7dAvg >= 3` | **Offload**, and set `progressionOffset = -1` |
| 3 | `dayNumber === block.retestDay` | **Retest day.** No training. |
| 4 | `hoursOnFeetYesterday > hoursBaseline * 1.4` | If kind is Strength, swap to Recovery. |
| 5 | `daysSinceLastSession >= 5` | `progressionOffset = -1`, session is the block's Mobility day |
| 6 | otherwise | Normal day from the template |

**Rule 1 is the most important one in the app.** On a high-pain day, the
session is not cancelled — it becomes short-foot work, which does not load the
fascia. The user still has a session, still completes it, still keeps the
streak. This is what stops the uninstall on the worst day.

## 3.2 Progression offset

- Applied to heel-raise prescription only. `-1` means use the previous block's
  sets × reps.
- Clears after **two consecutive days** with `painToday <= pain7dAvg`.
- Never goes below Block 2's prescription.
- Never positive. The plan does not accelerate.

## 3.3 In-session pain

`pain-check.tsx` already has a mid-session pain prompt path.

| Reported | Action |
|---|---|
| 0–4 | Continue. Acceptable discomfort. |
| 5+ | End the session. Mark complete. Set `progressionOffset = -1`. |

Copy when ended: `Stopping here. Tomorrow starts one step back.`

## 3.4 Missed days — the rule that must not be broken

The program runs on **dates, not completions**. Day 17 is day 17 whether or not
day 16 happened.

- Never queue a missed session
- Never show "you missed N days"
- Never break the streak for a system-assigned rest or offload day
- Day 84 arrives 84 days after start, regardless of attendance

The existing copy at `day-page.tsx:184-186` already states this. Make the engine
match it.

# PART 5 — RETESTS

## 5.1 The tests

Three, same three every time, ~4 minutes.

| id | Test | Measure | Per side |
|---|---|---|---|
| `calf` | Single-leg heel raises to failure | reps | yes |
| `balance` | Single-leg stand, eyes closed | seconds | yes |
| `arch` | Short-foot hold to failure | seconds | yes |

Symmetry is derived: `abs(L - R) / max(L, R) * 100`, rounded.

## 5.2 Levels

| Level | Calf reps | Balance sec | Arch sec | Symmetry |
|---|---|---|---|---|
| 1 | < 8 | < 5 | < 10 | > 30% |
| 2 | 8–14 | 5–10 | 10–20 | 20–30% |
| 3 | 15–21 | 11–20 | 21–35 | 12–20% |
| 4 | 22–28 | 21–30 | 36–50 | 6–12% |
| 5 | 29+ | 31+ | 51+ | < 6% |

**Levels move only on retest days.** Never on session completion, never on
streak, never on elapsed time. This is the app's only claim that cannot be
gamed, and it is worth nothing if it drifts.

Store thresholds in a config file, not inline.

## 5.3 Storage

```ts
type RetestResult = {
  blockIndex: number
  dayNumber: number
  date: string
  calf: { left: number; right: number }
  balance: { left: number; right: number }
  arch: { left: number; right: number }
  symmetryPct: number
  levels: { calf: number; balance: number; arch: number; symmetry: number }
}
```

Day 1 of the program runs the same three tests as the **baseline**. Store it as
`blockIndex: 0`. Without a baseline the first retest has nothing to compare to.

## 5.4 Wiring the Day sheet

`day-page.tsx` is unreachable. Fix:

- `program-page.tsx` day row tap → `/day?day={n}`
- Branch A: `dayNumber` is a past retest **with** a stored result
- Branch B: `dayNumber === block.retestDay` and it is today
- Branch C: `dayNumber` is a future retest
- Branch D: any ordinary day
- Past retest with **no** result → new state:
  `This retest wasn't completed. Levels held from the last one.`
- Bad `?day=` → `That day isn't part of your plan.` (currently returns `null`,
  producing a blank sheet)

`Start retest` at `day-page.tsx:144` currently calls `router.back()`. It must
run the three tests, store the result, recompute levels, and return to Branch A
showing the new numbers.

The program does not end. Its goal changes.

Trigger: the final retest is completed, or `dayNumber > lastBlock.endDay`.

**Weekly schedule:**

| Day | Kind | Exercises | Min |
|---|---|---|---|
| Mon | Strength | `heel_raise_plain`, `short_foot_single` | 8 |
| Wed | — | rest | — |
| Thu | Strength | `heel_raise_plain`, `band_inversion`, `hip_abduction` | 8 |
| Daily | — | morning stretch | 1 |

Retest every 28 days instead of 14.

**Copy for the transition**, in the existing brief slot:

```
{name}, you're through. Your calf went ↗ from 11 to 24.

About half of people lose this again within five years.
Two sessions a week is how you stay in the other half.
```

That framing is the entire reason someone pays after the pain is gone. Do not
replace it with a congratulation.

**Regression watch.** If a maintenance retest drops a level, or logged pain
rises above the maintenance baseline for 7 consecutive days, offer a return to
Block 4. Copy: `Your numbers slipped. Want to run Build again?`

# PART 7 — DERIVED VALUES

Replace every hardcoded number with a computed one.

| Where | Currently | Must become |
|---|---|---|
| `program-page.tsx:144` | `Block 2 of 4` | `blocks.length` |
| `home-page.tsx` streak | `🔥 7` | real streak |
| `progress-page.tsx:139` | `🔥 3` | same source as home |
| `progress-page.tsx:77-81` | `progress is ↗ 44%` | measured pain delta, 90-day window |
| `progress-page.tsx:163` | `88 Score` | computed — see below |
| `performance-card.tsx:97` | `↑ 43%` | delta between last two retests |
| Day list | hardcoded 15–28 | generated for the whole plan |

**Score formula** — must be explainable, because an unexplained number loses
trust within two weeks:

```
score = levelsAvg   × 50      // normalised 0–1 from the four levels
      + painTrend   × 30      // 90-day improvement, normalised
      + consistency × 20      // check-ins in last 14 days / 14
```

Recompute on retest, on pain-trend change, and on check-in — not on every
render.

**Streak counts a check-in, not a session.** A day is green if:
`painEntry exists` OR `session completed` OR `the day was system-assigned rest`.

One automatic freeze per week, accumulating to two. Restore within 48 hours of
a break, one tap. Never surface a lost streak as a failure.

# RULES THAT OVERRIDE EVERYTHING

1. **Never cheerful when logged pain is 5 or higher.** If the user reports pain
   and the app responds with celebration, it has called them a liar about their
   own body. This is how these apps get uninstalled.
2. **Never punish a miss.** No make-up sessions, no guilt copy, no broken streak
   for a rest day the app itself assigned.
3. **Levels move only on retests.** Nothing else touches them.
4. **Never invent a metric.** Only show what was measured: pain logged, reps
   counted, seconds held, days elapsed.
5. **Never promise a cure.** *Screening*, *program*, *exercises*. Never
   *diagnosis*, *treatment*, *cure*, *fix your flat feet*.
6. **A high-pain day still has a session.** Shorter, unloaded, but present.
