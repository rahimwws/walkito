If a task appears to require a visual change, stop and list it under
`NEEDS_DESIGN_DECISION` at the end of your report instead of doing it.

## P0.1 — Paywall legal block

**File:** `src/pages/offer/ui/offer-page.tsx`

The paywall currently has no trial length, no auto-renew disclosure, no Terms
link, no Privacy link, and no Restore Purchases. Apple requires all of these for
auto-renewable subscriptions. The app will be rejected without them.

Add below the plan rows, above or beside the Continue button, **using the
existing text styles already present in this file** — do not introduce new
typography:

```
7 days free, then $80.99/year. Cancel anytime.

Subscriptions renew automatically unless cancelled at least 24 hours before
the period ends. Manage or cancel in your App Store account settings.

Terms   ·   Privacy   ·   Restore Purchases
```

Requirements:
- The price in the disclosure must be read from the same source as the plan
  rows — never hardcoded a second time.
- When the boosted offer is active, the disclosure must show the boosted price
  ($46.99), not the standard one.
- If there is no free trial, delete the first line entirely. Do not state a
  trial that does not exist.
- Terms and Privacy must open real URLs. If none exist, add them to a config
  file and add `NEEDS_URL` to your report.
- Restore Purchases must call the real restore method and show the result
  (see P0.2).

# P1 — BROKEN PROMISES AND VISIBLE BUGS

Things that are wired but wrong, or promised but absent. Each one damages trust
in a category where users are already primed to expect a scam.

## P1.1 — The Day sheet is unreachable

**File:** `src/pages/day/ui/day-page.tsx`

No code pushes this route. It contains four branches (completed retest, retest
due, retest ahead, ordinary day) and none of them can ever be seen.

This screen carries the retest results — the only objective evidence the app
gives that it is working. It must be reachable.

Wire it:
- Tapping any day row in `program-page.tsx` opens `/day?day={n}`
- Tapping a completed checkpoint opens Branch A
- Tapping the current retest opens Branch B
- Tapping a future checkpoint opens Branch C
- Tapping an ordinary past or future day opens Branch D

Do not restyle `day-page.tsx`. Only make it reachable and make its branches
resolve correctly.

## P1.2 — Retest data exists only for day 14

Branches A/B/C select by day number, but only day 14 has data. A completed
checkpoint without data silently falls through to the future copy
(`Opens on…`), which is visibly wrong.

Required:
- Add retest data structures for all four block checkpoints
- A completed checkpoint with no stored result must show a real state, not the
  future copy. Copy: `This retest wasn't completed. Levels held from the last one.`
- `day-page.tsx:55` returns `null` on a bad `?day=` param, producing a blank
  sheet. Return a real state instead: `That day isn't part of your plan.`

## P1.3 — `Start retest` does nothing

`day-page.tsx:144` — the button calls `router.back()`. It must start the actual
retest flow: three tests, capture results, write them, update levels, then
return to the Day sheet showing Branch A with the new numbers.

If no retest flow exists in the codebase, build the logic only and reuse the
session player UI. Add to `NEEDS_DESIGN_DECISION` if that is not possible
without new UI.

## P1.4 — `Refer a friend, get 60% off`

`profile-menu.ios.tsx:45` promises 60% off. No code produces 60%.

Either:
- Implement referral: generate a code, a share sheet, a redemption path, and a
  discount that actually equals the number in the string; **or**
- Change the string to match what actually exists.

Do not ship a promise with nothing behind it.

## P1.5 — The gift is never delivered

`gift-sheet.tsx` — `Something for you` → `Open it` → nothing is named, valued,
or granted.

Either implement a real reward, or remove the entry point
(`header-actions.tsx:196`). An empty gift in a category where users have been
sold $1,700 insoles reads as bait.

## P1.6 — Discount numbers contradict each other

Four different numbers are shown to the same user:
- Paywall: `48%`, animating to `70%` when boosted
- Referral menu: `60% off`
- Win-back notification: `Take 70% off`

Unify. There must be one discount value, sourced from one place, and it must be
the real difference between the monthly and yearly price.

Verify the arithmetic: $12.99/mo × 12 = $155.88 against $80.99/yr is **48%**.
The `70%` claim is not supported by any price in the app. Either the boosted
price must produce 70%, or the number must change.

## P1.7 — Progress `44%` is not a real metric

`progress-page.tsx:77-81` — `Over the last 📅 7 days your progress is ↗ 44%.`

"Progress" as a percentage is not measurable and will read as false on a bad
day. Replace with measured values, using the same token structure and the same
styles:

```
Over the last 📅 90 days your morning pain went ↘ from 7 to 3.
```

Rules:
- Default window must be **90 days**, not 7. Pain fluctuates; a 7-day window
  will show worsening roughly half the time from noise alone.
- Keep the 7-day tab, but it must show a raw count, never a trend:
  `📅 5 of 7 days logged this week.`
- Colour and arrow must agree. Falling pain is good (green, ↘). Rising strength
  is good (green, ↗). Never show green when the underlying number got worse.
- When there is insufficient data: `📅 {n} days in. Too early to call a trend.`

# P2 — MISSING LOGIC

## P2.1 — The home brief: ten missing states

**File:** `src/pages/home/ui/home-page.tsx:46-87`

The docstring names eleven brief states and a ladder to select between them.
One is written. This is the first thing the user reads every day.

Implement the selection ladder, first match wins:

```
1. pain >= 7 today                  → flare
2. pain rose 3+ vs 7-day average    → spike
3. retest available                 → retest
4. hours on feet yesterday > baseline × 1.4  → overload
5. away 4+ days                     → return
6. session already done today       → done
7. program day < 8                  → early
8. pain fell over 30 days           → improving
9. block just changed               → new block
10. rest day assigned               → rest
11. otherwise                       → default
```

Copy for each, following the existing token structure exactly — grey frame
words, emphasised values, red for warnings:

| State | Copy |
|---|---|
| flare | `{name}, today is 🌙 3 minutes, sitting down. Nothing more.` |
| spike | `{name}, your pain went ⚠ from 3 to 7. Today is 🌙 offload only.` |
| retest | `{name}, it's been 📋 14 days — time to check where you stand.` |
| overload | `{name}, you were 👣 11 hours on your feet yesterday. Today is 🌙 recovery.` |
| return | `Welcome back, {name}. You have ▶️ one short session to ease in.` |
| done | `Done for today, {name}. That's ✅ 12 days in a row.` |
| early | `{name}, day 🔥 3 of 84. Today is ▶️ 4 minutes.` |
| improving | `{name}, your morning pain went ↘ from 6 to 3 this month.` |
| new block | `{name}, you're into 📋 Strengthen. The work changes from here.` |
| rest | `{name}, today is 🌙 rest. That counts.` |
| default | `{name}, your pain is 🟢 2 out of 10 and you have ▶️ one session today.` |

**Rule that must not be broken:** never show an upbeat state when today's

# COPY RULES FOR ANY STRING YOU WRITE

1. **Never cheerful on a bad day.** If logged pain is 5 or higher, no
   congratulation, no confetti, no upbeat framing.
2. **Never punish a miss.** No "you missed 3 days", no lost-streak language.
   The program runs on dates; the next day is the next day.
3. **Never promise a cure.** Use *screening*, *program*, *exercises*. Never
   *diagnosis*, *treatment*, *cure*, *fix your flat feet*.
4. **Never invent a metric.** Only show numbers that were measured: pain logged,
   reps counted, seconds held, days elapsed.
5. **Match the existing voice** — plain, short, lowercase-leaning, no jargon,
   no exclamation marks except where they already exist.
6. **Typographic consistency** — this codebase uses U+2019 curly apostrophes,
   en-dashes in ranges, em-dashes in blurbs. Match what surrounds your string.
   Note the existing inconsistency at `steps.ts:147` (U+2011 non-breaking hyphen
   in `pain‑free`) — leave it, do not "fix" it, as it may be deliberate.
