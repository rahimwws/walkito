# Tread — Onboarding copy deck

Replacement copy for all 19 onboarding steps, written to drop into the existing
UI with **zero visual changes**.

Every string below maps to an exact slot that already exists. Same step count,
same field types, same components. Only the words change, plus three places
where an existing dynamic-blurb pattern is extended.

---

## Principles behind this rewrite

**Every step gives something back.** Right now the user answers nine questions
before receiving anything. In this deck, seven of them return a fact, a reason,
or a reflection of what they just said.

**Promise speed, not cure.** The evidence says strength work beats stretching
at 3 months, but the two converge at 12 months. So the honest claim is
*faster*, never *the only thing that works*. First improvement lands at day
12–16 — that is the promise to make.

**Plain language.** No "AI-powered", no "personalised", no "revolutionary".
Restraint is what builds trust in a category where people have been sold
$1,700 insoles.

**Recognition is the value moment.** There is no scan and no physical test, so
the payoff has to come from the user reading a description of themselves and
thinking *that's exactly it*. Step 15 carries this.

## Step 15 — Building your plan ★ THE VALUE MOMENT

`building-step.tsx:29`

only thing that can make the user feel *understood* is reading themselves back.

| 1 | 0.0 s | Reflects what they told you |
| 2 | ~2.0 s | Names the pattern |
| 3 | ~4.0 s | States the promise |

**Line 3 — promise.** Fixed:

> Day 12–16 is defensible: subjective relief in the strength-training arm of
> Rathleff's trial began inside the first two weeks. Twelve weeks is the
> program length, not the promise — stating it here hands the user an exit date.

# IMPLEMENTATION NOTES

**Find-and-replace hazards.** This codebase uses U+2019 curly apostrophes
throughout onboarding. `steps.ts:146` writes it as the escape `&rsquo;`.
`steps.ts:147` uses a U+2011 non-breaking hyphen in `pain‑free` while every
other instance uses ASCII. Match what surrounds each string; do not normalise.

**`\n` is honoured** in titles — `typed-text.tsx:105` splits on it. Step 2's
two-line title depends on this.

**`{name}` substitution** happens at `onboarding-page.tsx:473-477` via
`withName`. With no stored name, the token and its surrounding comma are
dropped — so every line using `{name}` must still read correctly without it.
Check each one.

**Three new dynamic behaviours** are introduced here, all following the existing
`personalise.ts` pattern:
1. Table A — a line after step 9
2. Table B — line 2 of step 15
3. `RECOMMENDED` badge driven by the step 4 answer

None require a visual change. If any of them cannot be done without one, report
it rather than implementing it.
